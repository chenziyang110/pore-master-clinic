# 妙手净肤馆 · Pore Master Clinic

一间小小的净肤馆。放慢节奏，体验热敷、清理与舒缓护理的微距解压小游戏。

原生 HTML、CSS、Canvas 2D 与 Web Audio API 实现，全部内容都在 `index.html` 内。没有外部图片、字体、音频或运行时依赖，可直接离线打开。

## 画面与体验

- **护理工作台**：暖白、鼠尾草绿与细线器械图标；桌面端分开呈现护理记录与操作区，手机端采用紧凑的纵向布局。
- **两种肌理**：自然与柔和模式均由 Canvas 实时绘制；鼻翼、鼻头、下巴具有不同的表面起伏、毛孔分布和细微纹理。统一侧光与柔和阴影，降低随机噪点；三类目标在轮廓、破口和排空后的形态上保持区别。
- **细致反馈**：热敷凝露、局部放大镜、双指挤压、夹取进度与速度提示、残留擦拭，以及收集盘检视。镜面边缘保持准星与实际触点一致。
- **护理引导**：首次游玩依次标出黑头、白头和深层目标，跟随目标状态提示动作与下一件工具；可跳过，也可在操作指南重新打开。实时软化、压力与冰膜覆盖反馈帮助掌握力度。
- **完整护理流程**：五位顾客、各自的可选目标、器械升级、冰膜收尾、同一构图下的护理前后对比、局内存档和已完成护理记录。
- **键盘与触屏**：键盘可选择目标并按住完成护理，辅助成绩单独记录；触屏跟踪双指身份，系统取消触摸时安全释放。手机竖屏与横屏分别布局，小屏优先保留操作空间。
- **顾客与休息**：五位顾客使用各自的矢量头像；打开暂停弹窗、完成结算或页面进入后台时，停止模拟与画布重绘。

游戏中的肤质、刺激度和处理反馈是玩法表现。

## 开始游玩

下载或克隆仓库后，直接在现代浏览器中打开 `index.html`。

也可以启动本地静态服务：

```bash
python3 -m http.server 8080
```

然后访问 `http://localhost:8080`。

| 工具 | 桌面快捷键 | 操作 |
| --- | --- | --- |
| 热喷 | `1` | 按住并缓慢扫过皮肤；充分软化的黑头可以直接夹取 |
| 粉刺针 | `2` | 按住查看放大镜，松开破口；也可先松动黑头，再夹取 |
| 轻柔挤压 | `3` | 在瑕疵旁按住并向中心推；触屏也支持双指捏合 |
| 细胞夹 | `4` | 夹住已软化、松动或露头的目标，缓慢向外拖动；也能拾取皮肤上的提取物 |
| 清洁棉签 | `5` | 拖动擦净残留；再次选择可更换棉签 |

清理全部区域后，可以亲手涂抹冰膜，也可以选择一键敷膜，随后查看护理记录。顶部接诊台可切换顾客并升级器械。

**键盘辅助**：按 `Tab` 聚焦护理画布，用方向键选择目标，`1`–`5` 切换工具，按住 `空格` 或 `Enter` 使用，松开即停止。粉刺针在松开时完成破口；`Esc`、失去焦点或切出页面会取消动作。全部清理后按 `6` 进入冰膜，再逐处按住涂抹。一局中使用过辅助操作，整局就归入键盘辅助成绩；开始新局后重新判定。

当前护理会自动保存在本浏览器：顾客、目标状态、局内分数、残留、收集物与冰膜进度都能在刷新后接着进行。松手、切出窗口或页面进入后台时会结束当前动作并保存，恢复后需要重新按住操作。收入、已购器械、完成记录与局内进度一起保存，避免结算只写入部分数据。损坏的局内快照会回到新局；无法读取的整份存档会原样保留，并提示重试。

**多个页面接续**：同一浏览器中，一次只在一个页面继续护理。第二个页面先暂停，点击“在这里继续”后，原页面先保存并停下，新页面读取最新进度再接手。等待交接时可以取消；关闭原页面后，也可以从另一页继续。暂停的旧页调整尺寸、回到前台或关闭时，都不会把它的旧进度写回去。

在接诊台点击标有“护理中 · 继续”的顾客，会回到当前进度。已有进度时，重新开始需要确认。结算对比图支持拖动，也可聚焦后用方向键调整分割线，`Home` / `End` 移到两端；下一次护理的数量可在“下一次护理设置”中选择。

## 护理表现与记录

游戏保持轻松节奏，没有倒计时或硬失败。停下来休息不会清空连贯步骤，误操作会中断连贯。当前刺激度可以通过清理与冰膜舒缓，但累计刺激和误操作仍保留在本局记录中。评级结合这两项表现，基础酬金照付，小费随评级变化。

最高分只记录已经完成的护理，按顾客、数量设置和输入方式分别保存。五位顾客各有一项可选目标，接诊台显示达成情况和个人最佳表现；最近 60 次护理保存在浏览器中，接诊台展示最近 8 次，包括目标结果与使用器械。

如果需要公开试玩，可在仓库 **Settings → Pages → Build and deployment** 中选择 **Deploy from a branch**，使用 `main` 分支和 `/ (root)` 目录。仅推送源码不会自动启用 Pages。

## 开发

无需构建。编辑 `index.html` 并刷新浏览器即可。

开发回归需要 Node.js 22 或更新版本：

```bash
npm ci
npm test
```

测试使用 jsdom 的 DOM 事件和 Skia Canvas 像素渲染，覆盖触点身份、失焦释放、跨页面存档、收集一致性、场景迁移、工具规则、评级记录、新手引导，以及从八处目标到冰膜结算的完整键盘流程。共享存储工具模拟多个独立窗口、异步 StorageEvent 与 Web Locks 队列，验证接管、延迟通知、取消和关闭；存储失败检查验证结算数据一起保留或一起提交。CSS 排布、音效质量、真机触摸和耗电仍需浏览器及设备验证；游戏本身不依赖这些开发包。

v3 存档以一份 profile 保存进度、余额、器械、记录和引导状态，旧键仅用于迁移。支持 Web Locks 的环境使用浏览器互斥协调写入；缺少该 API 时使用所有者租期和版本检查，极端同时抢占时的原子性受限。存储不可用时仍可进行当前护理，并显示无法保存的提示。

- `CONFIG`：玩法物理和数值参数。
- `CLIENTS` / `UPGRADES`：顾客内容与器械配置。
- `renderSkinTexture()`：基础皮肤、面部区域、毛孔和毫毛。
- `renderRealBlackhead()` / `renderRealWhitehead()` / `renderRealCyst()`：三类清理目标的外观。
- `bindCanvasInteractions()`：鼠标、触控与对比图操作。
- 页面顶部 `<style>`：颜色、排版、响应式布局与交互状态。

`push-to-github.sh` 只推送当前已提交分支，不强制覆盖远端，也不会自动暂存工作区文件。首次使用前需要在本机完成 GitHub 认证。

## 版本记录

- **原始版本**：完整导入上传的游戏源码，保留在 Git 历史中。
- **护理工作台改版**：重排界面、统一图标和文案、细化皮肤与病灶材质，并同步优化小屏布局、触摸取消处理和弹窗键盘行为。
- **操作细节优化**：精简重复标记，增大手机提示文字；统一器械、放大镜与操作反馈；修复已清理部位的冰膜引导，完善当前顾客继续、重开确认及键盘对比操作。
- **稳定性与进度恢复**：确定性排布和完整场景迁移、统一快照构图、唯一收集归属、触点身份跟踪，以及包含当前护理的自动存档。
- **第一局与护理记录**：三类目标逐处引导、工具规则和提示共用、累计操作表现、按档完成成绩、顾客可选目标和历史记录。
- **画面与辅助操作**：统一皮肤光照和目标形态，增加五位顾客头像，压缩小屏界面；提供完整键盘护理，并暂停后台、弹窗和结算期间的画布更新。
- **页面接续与统一存档**：多个页面之间明确接管护理，停止旧页写入；将局内进度、收入、器械和完成记录合并提交，兼容迁移原有进度。
