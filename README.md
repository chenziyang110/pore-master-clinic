# 妙手净肤馆 · Pore Master Clinic

一间小小的净肤馆。放慢节奏，体验热敷、清理与舒缓护理的微距解压小游戏。

原生 HTML、CSS、Canvas 2D 与 Web Audio API 实现，全部内容都在 `index.html` 内。没有外部图片、字体、音频或运行时依赖，可直接离线打开。

## 画面与体验

- **护理工作台**：暖白、鼠尾草绿与细线器械图标；桌面端分开呈现护理记录与操作区，手机端采用紧凑的纵向布局。
- **两种肌理**：自然与柔和模式均由 Canvas 实时绘制；鼻翼、鼻头、下巴具有不同的表面起伏、毛孔分布和细微纹理。统一侧光与柔和阴影，降低随机噪点；三类目标在轮廓、破口和排空后的形态上保持区别。
- **细致反馈**：热敷凝露、局部放大镜、双指挤压、夹取进度与速度提示、残留擦拭，以及收集盘检视。镜面边缘保持准星与实际触点一致。
- **护理引导**：首次游玩依次标出黑头、白头和深层目标，可跳过，也可在操作指南重新打开。鼠标指向、触屏操作或键盘选中一处后，“这处”提示按该目标的状态推荐工具；未选中目标时才提供整体的“下一处”建议。实时软化、压力与冰膜覆盖反馈帮助掌握力度。
- **完整护理流程**：五位顾客各有护理重点、可选目标和回访话语；从清理、收集到冰膜、前后对比与结算，逐步留下五枚护理印记。器械仍为三件升级，五枚印记集齐后明确显示本章完成。
- **键盘与触屏**：键盘可选择目标并按住完成护理，辅助成绩单独记录；触屏只跟踪在画布内开始的手指，系统取消触摸时安全释放。热敷按持续时间计算，夹取按真实拖动速度判断，棉签和冰膜连续覆盖移动路径。手机竖屏与横屏分别布局，小屏优先保留操作空间。
- **顾客与休息**：五位顾客使用各自的矢量头像；未完成护理切换顾客时先确认。静止画面、暂停弹窗、完成结算或页面进入后台时停止排帧，有操作后恢复；活动画面最多约 60 帧/秒。
- **声音与偏好**：操作音使用统一音量、柔和起音和并发限制；静音、失焦、后台及页面交接会停止声音。肌理和声音选择独立保存，完成护理后仍保留。系统选择减少动态效果时，保留提示和操作判定，取消大范围飞行、震动和漂移。

游戏中的肤质、刺激度和处理反馈是玩法表现。

## 开始游玩

下载或克隆仓库后，直接在现代浏览器中打开 `index.html`。

也可以启动本地静态服务：

```bash
python3 -m http.server 8080
```

然后访问 `http://localhost:8080`。

| 工具 | 桌面快捷键 | 操作 |
| --- | --- | --- |
| 热喷 | `1` | 按住并缓慢扫过皮肤；充分软化的黑头可以直接夹取 |
| 粉刺针 | `2` | 按住查看放大镜，在画布内松开破口；移出画布再松开取消，也可先松动黑头再夹取 |
| 轻柔挤压 | `3` | 在瑕疵旁按住并向中心推；触屏也支持双指捏合 |
| 细胞夹 | `4` | 夹住已软化、松动或露头的目标，缓慢向外拖动；也能拾取皮肤上的提取物 |
| 清洁棉签 | `5` | 拖动擦净残留；再次选择可更换棉签 |

清理全部区域后，可以亲手涂抹冰膜，也可以选择一键敷膜，随后查看护理记录。顶部接诊台可切换顾客并升级器械。

**当前目标提示**：先看眼前目标是否需要热敷、破口、露头或擦净，再跟随“这处”建议换工具。例如，未破口的深层目标会先建议用针，已软化的黑头可以直接夹取。粉刺针只在画布内正常松手时执行；触摸被系统取消、窗口失焦或切到后台时会取消动作，不会在旧位置补下一针。

**键盘辅助**：按 `Tab` 聚焦护理画布，用方向键选择目标，`1`–`5` 切换工具，按住 `空格` 或 `Enter` 使用，松开即停止。粉刺针在松开时完成破口；`Esc`、失去焦点或切出页面会取消动作。全部清理后按 `6` 进入冰膜，再逐处按住涂抹。一局中使用过辅助操作，整局就归入键盘辅助成绩；开始新局后重新判定。

当前护理会自动保存在本浏览器：顾客、目标状态、局内分数、残留、收集物与冰膜进度都能在刷新后接着进行。松手、切出窗口或页面进入后台时会结束当前动作并保存，恢复后需要重新按住操作。收入、已购器械、完成记录与局内进度一起保存，避免结算只写入部分数据。损坏的局内快照会回到新局；无法读取的整份存档会原样保留，并提示重试。

**保存异常**：未能写入时，工作台和弹窗会持续显示未保存提示。当前页面仍可保留这次护理；请保持页面打开，存储恢复后点击“重试保存”。成功保存后提示才消失。如果另一页已有较新进度，会先进入接续提示，明确说明使用已保存进度将放弃本页未保存的操作。

**多个页面接续**：同一浏览器中，一次只在一个页面继续护理。第二个页面先暂停，点击“在这里继续”后，原页面先保存并停下，新页面读取最新进度再接手。等待交接时可以取消；关闭原页面后，也可以从另一页继续。暂停的旧页调整尺寸、回到前台或关闭时，都不会把它的旧进度写回去。

在接诊台点击标有“护理中 · 继续”的顾客，会回到当前进度。已有进度时，重新开始或接待另一位顾客需要确认；取消后保留原局。结算对比图支持拖动，也可聚焦后用方向键调整分割线，`Home` / `End` 移到两端；下一次护理的数量可在“下一次护理设置”中选择，刷新恢复后选中状态保持一致。

**护理数量**：“按顾客安排”使用各自的默认配方；自由选择 8 处或 11 处时，按该顾客原有三类目标的比例取整分配，保证总数正确。小林仍以白头为主，薇薇仍以深层为主，黑头专场始终只有黑头；数量变化不会把五位顾客变成同一种组合。

## 护理表现与记录

游戏保持轻松节奏，没有倒计时或硬失败。停下来休息不会清空连贯步骤，误操作会中断连贯。即时刺激度可以通过清理与冰膜舒缓，但累计刺激和误操作仍保留在本局记录中。工作台单独显示“本局表现”、误操作次数和累计刺激，点击可查看评级规则。结算会解释夹断、力度或落点失误、累计刺激对等级的影响；可选目标与护理等级分别展示。基础酬金照付，小费随评级变化。

最佳记录只计入已经完成的护理，按顾客、数量设置和输入方式分别保存，并优先展示最佳护理等级。原始最高分包含连贯和器械奖励，不适合直接当作手法变好的证明；结算中也会标明这一点。最近 60 次护理保存在浏览器中，接诊台展示最近 8 次，包括目标结果与使用器械。

具体达成条件和当前进度可在“护理手记”或操作指南查看。每位顾客首次达成目标时，留下对应印记并额外获得 **¥60**；结算分别列出护理酬金、评级小费与首次目标奖励。该奖励每位顾客仅领取一次，换数量、换输入方式、刷新或重复打开结算都不会再次发放。已有存档中达成过的目标直接计入印记，不补发这笔新奖励。

接诊台显示已收集的印记和下一位目标；完成五个目标后，本章完成，工作台留下完成标记。可以继续回访、改善护理表现或随时停下。三件器械购齐后，后续收入继续保留，不再增加必须购买的项目。印记使用现有护理记录派生，与余额、器械和进度一起保存，不依赖另一份独立的成长存档。

## 开发

无需构建。编辑 `index.html` 并刷新浏览器即可。

开发回归需要 Node.js 22.22.2+、24.15.0+ 或 26+（与当前 jsdom 的版本要求一致）：

```bash
npm ci
npm test
```

测试使用 jsdom 的 DOM 事件和 Skia Canvas 像素渲染，覆盖触点身份、输入速率、失焦释放、跨页面存档、收集一致性、场景迁移、工具规则、评级记录、新手引导、顾客切换和偏好，以及从八处目标到冰膜结算的完整键盘流程。共享存储工具模拟多个独立窗口、异步 StorageEvent 与 Web Locks 队列，验证接管、延迟通知、取消和关闭；存储失败检查验证结算数据一起保留或一起提交。目标提示与配方回归检查所选目标的建议、针取消边界，以及自由数量下的顾客差异。成长回归检查首奖去重、旧记录继承、五印记完成和等级反馈；保存反馈回归检查常驻提示与恢复重试。音效测试检查声源、暂停、恢复及清理；性能测试检查休眠唤醒和刷新率一致性。

GitHub Actions 的 `Game quality` 在推送 `main` 或提交 PR 后，以 Node.js 22 和 24 运行同一组回归测试。游戏本身不依赖这些开发包。验收范围、复查步骤和实机边界见 [ACCEPTANCE.md](ACCEPTANCE.md)；后续 iOS / Android 真机与首次玩家的记录表及准入标准见 [PLAYTEST.md](PLAYTEST.md)。目前尚未执行真实玩家研究或实体手机体验验证，自动化与浏览器尺寸检查不代表这些验证已经完成。

v3 存档以一份 profile 保存进度、余额、器械、记录和引导状态，旧键仅用于迁移。支持 Web Locks 的环境使用浏览器互斥协调写入；缺少该 API 时使用所有者租期和版本检查，极端同时抢占时的原子性受限。存储不可用时仍可进行当前护理，并显示无法保存的提示。

- `CONFIG`：玩法物理和数值参数。
- `CLIENTS` / `UPGRADES`：顾客内容与器械配置。
- `renderSkinTexture()`：基础皮肤、面部区域、毛孔和毫毛。
- `renderRealBlackhead()` / `renderRealWhitehead()` / `renderRealCyst()`：三类清理目标的外观。
- `bindCanvasInteractions()`：鼠标、触控与对比图操作。
- 页面顶部 `<style>`：颜色、排版、响应式布局与交互状态。

`push-to-github.sh` 只推送当前已提交分支，不强制覆盖远端，也不会自动暂存工作区文件。首次使用前需要在本机完成 GitHub 认证。

## 版本记录

- **原始版本**：完整导入上传的游戏源码，保留在 Git 历史中。
- **护理工作台改版**：重排界面、统一图标和文案、细化皮肤与病灶材质，并同步优化小屏布局、触摸取消处理和弹窗键盘行为。
- **操作细节优化**：精简重复标记，增大手机提示文字；统一器械、放大镜与操作反馈；修复已清理部位的冰膜引导，完善当前顾客继续、重开确认及键盘对比操作。
- **稳定性与进度恢复**：确定性排布和完整场景迁移、统一快照构图、唯一收集归属、触点身份跟踪，以及包含当前护理的自动存档。
- **第一局与护理记录**：三类目标逐处引导、工具规则和提示共用、累计操作表现、按档完成成绩、顾客可选目标和历史记录。
- **画面与辅助操作**：统一皮肤光照和目标形态，增加五位顾客头像，压缩小屏界面；提供完整键盘护理，并暂停后台、弹窗和结算期间的画布更新。
- **页面接续与统一存档**：多个页面之间明确接管护理，停止旧页写入；将局内进度、收入、器械和完成记录合并提交，兼容迁移原有进度。
- **体验收尾与持续回归**：统一不同设备上的输入节奏，补齐连续擦拭与手指识别；空闲画面按需休眠，音效统一输出并可靠暂停；完善顾客切换、档位显示和偏好保留，加入持续回归检查。
- **当前目标与有限成长**：提示跟随当前目标，针移出画布后松手可取消；自由数量保留顾客配方特点。持续展示未保存状态并提供重试；增加五枚印记、每位首次目标奖励、回访及章节完成反馈，区分即时刺激、累计表现和含器械奖励的原始分数。
