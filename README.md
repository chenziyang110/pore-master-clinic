# 妙手净肤馆 · Pore Master Clinic

慢慢清理，发现小惊喜。闯关收集发饰与裙子，为首页穿着补丁旧裙的小女孩搭配一身喜欢的衣服。

**公开试玩：[https://pore-dressup-n7q4.candid-otter-5800.chatgpt.site/](https://pore-dressup-n7q4.candid-otter-5800.chatgpt.site/)**

当前公开站点已发布小女孩换装版本，可直接用手机浏览器打开。

原生 HTML、CSS、Canvas 2D 与 Web Audio API 实现，游戏和换装插画都在 `index.html` 内。插画使用内联 SVG，没有外部图片、字体、音频或运行时依赖，可直接离线打开。

## 现在怎么玩

1. 首页先见到穿着旧裙子的小女孩，点击“进入游戏 · 帮小女孩装扮”。
2. 按提示热敷、清理、收集并擦净，最后完成舒缓冰膜，进入下一关。
3. 特定关卡的护理目标中藏着发饰或裙子。取出时会出现“你的运气超棒！”的发现提示，完成这一关后正式收进衣橱。
4. 从首页、底部“衣橱”或过关页进入衣橱，点击已解锁的物品换装。发饰与裙子可以自由组合，也能摘下发饰或穿回旧裙子。

护理界面顶部只显示当前关卡，工具和操作提示留在操作区。游戏不展示错误率、误操作次数、护理评分或评级；衣服奖励与评分无关，按关卡和完成进度发放。

## 关卡与礼物

前两关是轻松入门：第 1 关只有 3 处黑头，第 2 关只有 4 处黑头。第 3 关开始逐步加入白头与双洞相连的黑头，后续关卡再增加数量和类型。

| 关卡 | 可发现的礼物 |
| --- | --- |
| 第 3 关 | 莓果蝴蝶结 |
| 第 5 关 | 晴空小裙子 |
| 第 6 关 | 小星星发夹 |
| 第 9 关 | 丁香花发箍 |
| 第 10 关 | 蜜桃花边裙 |
| 第 12 关 | 莓果蝴蝶结，再次发现 |
| 第 15 关 | 小星星发夹与紫藤花裙子，同关获得 |

发饰从第 3 关开始，每 3 关出现一次；裙子从第 5 关开始，每 5 关出现一次。两种周期重合时可以同时发现。当前衣橱有 3 件发饰和 3 条裙子，同类物品按顺序循环；重复发现不会重复增加拥有数量，也不会改变已经穿戴的搭配。

关卡可以继续游玩，不需要达到某个等级或分数才能获得礼物。中途发现的礼物会随本局进度保存，完成护理后才解锁穿戴。

## 清理画面与操作

黑头身体为光滑的浅色，仅顶端呈黑色，没有横向条纹。取出后的洞口使用浅肤色或浅粉色，黑头不会出血；部分白头可以出现少量血珠，并非每个洞口都有血。双洞相连的黑头共用一个目标和一根提取物，处理后两个洞口一起清空。

| 工具 | 快捷键 | 操作 |
| --- | --- | --- |
| 热喷 | `1` | 按住并缓慢扫过；充分软化的黑头可以直接夹取 |
| 粉刺针 | `2` | 按住查看放大镜，在画布内松开破口；移出画布再松开可取消 |
| 轻柔挤压 | `3` | 在目标旁按住并向中心推；触屏也支持双指捏合 |
| 细胞夹 | `4` | 夹住已软化、松动或露头的目标，缓慢向外拖动；也能拾取提取物 |
| 清洁棉签 | `5` | 拖动擦净残留；再次选择可以更换棉签 |
| 舒缓冰膜 | `6` | 全部清理后进入，按住涂抹；也可选择一键敷膜 |

**键盘**：用 `Tab` 聚焦护理画布，方向键选择目标，数字键换工具，按住 `空格` 或 `Enter` 操作，松开停止。粉刺针在松开时执行；`Esc`、失焦或切到后台会取消当前动作。

**鼠标与触屏**：根据目标状态跟随工具建议。拖动保持缓慢，触摸被系统取消、旋转屏幕或切换页面时会安全停手，回来后重新按住即可继续。工具区、衣橱与弹窗支持手机竖屏和横屏。

游戏中的皮肤与处理反馈仅为虚构玩法表现。

## 进度、换装与保存

进度自动保存在当前浏览器。关卡、当前护理、已发现的礼物、衣橱已解锁物品和当前穿搭使用同一份 `PROFILE` 存档写入，避免过关与衣服只保存一半；刷新后可以接着玩。旧版存档保留，新加入的衣橱数据会补上默认值。

- **保存异常**：未写入成功时会持续显示提示。保持页面打开，存储恢复后点击“重试保存”；提示消失后再离开。无法读取的整份存档会保留原内容，不会直接覆盖。
- **多个页面接续**：同一浏览器中一次只在一个页面继续。第二页先暂停，点击“在这里继续”后接续最新存档；旧页停止操作，避免旧进度覆盖新进度。等待时可以取消。
- **另一页已有较新进度**：先确认接续提示，再决定是否使用已保存进度；这会放弃本页尚未保存的操作。
- **浏览器范围**：存档属于当前浏览器与网站来源，不会自动跨设备同步；本地文件、本地服务与线上站点也不共用存档。

## 本地运行

下载或克隆仓库后，直接在现代浏览器中打开 `index.html`。也可以在仓库目录运行：

```bash
python3 -m http.server 8080
```

随后访问 [http://localhost:8080](http://localhost:8080)。

## 构建与发布

```bash
npm run build
```

`scripts/build-static.cjs` 只使用 Node.js 标准库，无需先安装开发依赖。它清理仓库自己的 `dist` 目录，再复制 `index.html` 和 `favicon.svg`；测试、文档和 QA 页面不会进入产物。

`vercel.json` 使用静态项目配置，构建命令为 `node scripts/build-static.cjs`，输出目录为 `dist`。其他静态托管平台也可直接发布 `dist`。GitHub 提交、Actions 检查与线上部署是不同步骤；推送是否自动发布取决于托管平台设置，应单独确认线上部署对应的提交。

## 测试与检查

使用 `package.json` 所要求的 Node.js 版本，安装锁定的开发依赖后运行：

```bash
npm ci
npm test
```

主要检查入口：

- [tests/wardrobe.test.cjs](tests/wardrobe.test.cjs)：礼物周期、发现与穿戴、保存和恢复。
- [tests/chapter-flow.test.cjs](tests/chapter-flow.test.cjs)：按关卡推进的完整护理流程。
- [tests/pore-appearance.test.cjs](tests/pore-appearance.test.cjs)：黑头外观、空洞、出血与双洞目标。
- 现有输入、声音、存档、跨页接续和渲染测试继续覆盖基础能力。

[Game quality 工作流](.github/workflows/quality.yml) 在推送 `main` 或提交 PR 时使用 Node.js 22/24 执行回归。本次提交是否通过，请查看对应的 GitHub Actions 结果。

启动本地静态服务后，可打开 [qa/responsive-check.html](qa/responsive-check.html) 检查多个视口；真实设备的安全区、系统手势和触控感受仍需真机观察。
